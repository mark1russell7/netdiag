netdiag

Find the cause of a network problem at any layer, and get the next step.

The demos run the diagnosis model of netdiag in your browser. They send no packets: you give the observations, a simulated network gives them, or a report of a real check gives them.

  • Name the cause Pick what you observed, and see the probable causes.
  • Find a hidden fault Run the best probe until one cause is clear.
  • Score the catalog Make each fault many times, and hold each recall with a bar.
  • Read a check report See the layers, the causes and the next step of a real check.

          3. Score the catalog in a simulated lab

          The lab makes each fault many times, and the probes observe it. scoreLab gives the recall of each fault with its Wilson interval. labGate holds the lower end of each interval with a bar.

          The lab draws each observation from the likelihoods of the catalog. Thus a recall here tests the model on its own assumptions, not on real networks. The real bars come from the kernel lab, with faults on real networks.

                  Install

                  pnpm add @mark1russell7/netdiag 
                  import { STANDARD_CATALOG, diagnose } from "@mark1russell7/netdiag/diagnosis";

const result = diagnose(STANDARD_CATALOG, [
  { feature: "icmp.reply", value: "none", primary: true },
  { feature: "tcp.connect", value: "connected", primary: true },
]);
// result.causes[0].id is "filter.icmp": a filter blocks ICMP, and the host is up.
